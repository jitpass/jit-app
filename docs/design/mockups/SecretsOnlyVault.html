Only secrets go into the vault

Protecting a .env today moves every line into the vault, so a group of 14 entries can hold one real secret. After this change, only credentials go to the vault. Settings like URLs, IDs and file names stay as plain text next to the profile, and the file still works exactly as before.

Every name below is made up. The billing-sync folder has the same shape as a real file that went into the vault as 14 entries: one client secret, a client ID, a URL, three file names, and three names that say secret but hold a file path.

The rule

A value goes into the vault when jit scan counts it as a secret. That's the same test Findings uses, from the same code (EnvFileCacheNeedles), so the Findings count and the Vault count can't disagree. It judges the value, not only the name.

  • vault
    SecretsValues scan counts as credentials: known token formats, and secret-looking names holding random-looking values. BILLING_CLIENT_SECRET goes here.
  • check
    Names that look like secrets, values that don'tEXPORT_SECRETS_FILE=exports/secrets.csv. Scan flags the name and can't confirm the value. These go to the vault unless you move them: a setting left in the vault costs a Touch ID, and a secret left in plain text is a leak.
  • plain
    SettingsEverything else: BILLING_URL, BILLING_CLIENT_ID, REPORT_DIR, KEEP_REPORTS. These stay plain text with the profile. The live file still serves them, and to any program, since they were never secret.

1 · Protect asks with the split

Today this is an alert listing file paths. It becomes a sheet: one card per file, showing what goes to the vault and what stays, and each line can be moved. The MCP config that reads the same .env is listed as covered, not as a second job. That's the case that failed on 2026-09-27 and is fixed in jit #182.

2 · What changed says it once

The What Changed sheet counts secrets, not lines, and names where the settings went.

3 · The Vault window shows secrets, and settings apart

The count next to each profile is secrets only. Settings get their own section under them: plain text, readable without Touch ID, and each one can be moved into the vault if it turns out to be a secret.

3b · Take specific values back out of the vault

Any secret can go back to plain text: one row, or several selected with ⌘-click. It's the same place a setting would have gone, and the file keeps working. Before anything moves, the sheet says what it costs: the value is readable by anything on the Mac, and it may show up in Findings again.

4 · Groups protected before this change

Profiles already in the vault still hold their settings. The Vault window says so once, in its banner, and one sheet moves them out. Classifying them means reading the values, so it takes one Touch ID for all the groups at once.

5 · The terminal says the same

jit migrate's plan today says "EVERY variable moves to the vault (ordinary config too, so the file still works)". It becomes:

[.env file] 1 → secrets move to the vault; settings stay as plain text, and the file keeps working • ~/code/billing-sync/.env 2 to the vault, 7 settings ! EXPORT_SECRETS_FILE goes to the vault: the name says secret, the value can't be told keep it plain: jit migrate ~/code/billing-sync/.env --setting EXPORT_SECRETS_FILE

What changes underneath

  • 1
    A profile can hold a plain valueToday every entry points into the vault. An entry can now be either a vault pointer or a literal. jit run, export and the live mount read both. It's the largest part, and every reader of a profile needs a test that fails without the change.
  • 2
    The split happens at protect timeApplyEnvFile sends only what EnvFileCacheNeedles claims, plus the names to check, to the vault. --setting NAME and --secret NAME override, and the sheet's Vault/Setting controls pass them.
  • 3
    The live mount serves settings to everyoneA program without a grant reads the real settings and a decoy only for each secret. That's closer to what it expects than today's all-decoy file.
  • 4
    Backups and Undo don't changeThe file is still backed up whole into the vault before it's rewritten, so Undo restores it exactly as it was.
  • 5
    Move out and move injit profile settle (name open) moves settings out of existing profiles. The Vault window's Move to Vault and Move Out of Vault… use the same code for single entries.

Open decisions

  1. Names that look like secrets but values that don't: vault or plain by default?A setting kept in the vault costs a Touch ID. A secret kept in plain text is a leak, and the scan would flag it again.Recommend: vault by default, flagged Check this.
  2. Show setting values in the Protect sheet before Touch ID?They're already plain text on disk, and seeing them is how you tell a setting from a secret. But the sheet puts them on screen.Recommend: show settings; secrets always as dots.
  3. Where to announce the cleanup for old profilesA banner in the Vault window only, or also a Findings row?Recommend: Vault window only. It isn't an exposure, so it doesn't belong in Findings.
  4. Moving a counted secret out: allowed, or refused?Allowing it means one click can leak a real secret. Refusing it means you can't overrule the scan when it's wrong.Recommend: allow it, with the warning on the row and Cancel as the default button.
  5. The name of the cleanup commandjit profile settle, jit vault slim, or jit migrate settings.Recommend: jit migrate settings, since migrate is where the split is made.
