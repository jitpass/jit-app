Grants Redesign

Let claude under iTerm2 use mcp-caido and mcp-urlscan, until you revoke it.

The sheet is that sentence, filling in blank by blank, and it is word for word what the disclosed Touch ID will ask. This version matches jit/design/standing-grants.md: a grant carries its own key, so it never asks again while it exists, and it survives screen lock, a service restart and a reboot. The schedule from the previous draft is gone. It was solving the wrong problem.

It also fixes the bug you found. New Grant listed profiles from ~/.jit/profiles only. That folder does not exist here, every profile on this Mac is kept beside a project, so nothing could be ticked and the button stayed grey with no word about why.

You never pick a folder. An earlier draft made you choose one first, which was the wrong question: a grant covers the secrets themselves, so the folder reaches nothing after the grant is made. jit finds your profiles instead, from the folders it already has on record in mounts.yaml, the folders your programs are running in, and the global store. You get one list of all ten, you filter it, you tick what you want. The folder is printed under each name only so two similar profiles can be told apart.

Three things the design forces, visible below. Until revoked is offered for Every copy, never for One process, because a pid cannot survive a reboot. A rotated secret stops being served, so the window has to say so. Revoke deletes the grant's key, so the confirmation says what that means.

New Grant · the sentence, filling in

One sheet, not a wizard: you do this rarely and you want to read the whole decision before spending a Touch ID. Unanswered blanks stay visible in grey, so what is missing is legible without hunting for the disabled button.

Grants window · what a standing grant looks like afterwards

A standing grant has no deadline to count down, so the eyebrow carries the only state that matters: is it serving right now. Green when it served in the last minute, grey when it is simply standing. Both are healthy, which is why neither is amber.

What changed from the last draft

  • 1
    Schedule removed, Until revoked added.Days and hours were a way to bound a grant that had to be bounded. A grant with its own key does not, so the schedule answered a question the design no longer asks. It stays drawn in the previous version if it ever returns.
  • 2
    Until revoked only for Every copy.A standing grant anchors to the app's executable path, which survives a reboot. One process anchors to a pid, which does not, so it keeps a deadline and the sheet says why.
  • 3
    Rotation has a state now.The design makes a rotated secret stop serving silently. Silent is fine for the engine and wrong for a window, so it gets an eyebrow, a count, the secret's name and a Re-approve.
  • 4
    Revoke deletes a key, so it asks once.Still free, still no Touch ID, still the easiest thing in the window. The alert exists because "revoke" no longer just forgets something.
  • 5
    No expiry column.Grants list a deadline today. Most grants will not have one, so the row spends that room on what it covers and when it last served.
  • 6
    The Project row is gone, and so is choosing a folder.It read as a scope and was not one: the folder never reaches the serve path. Two drafts tried to relabel it; the right answer was to delete it. jit lists every profile it can find, you filter and tick, and the folder is printed under each name only to tell two apart.
  • 7
    One wire change this needs.Today grant_create carries profile names plus a single folder. A machine-wide list can hand it names from two different folders, so the field becomes a name-and-folder pair per profile. The agent still resolves the names itself, which is the rule that stops anything naming one profile on the prompt and granting another.

Two pieces the design system does not have yet

Your rule is that a value missing from the system gets added to it, not invented in a view. These two are both additions to windows.md in the same pass, and both are drawn above.

  • 1
    A wide pill in a segmented control.Until revoked sits beside four short durations. The track already allows it; the page should say a pill may carry a phrase when it is a different kind of answer, not a longer one.
  • 2
    A detail row under a grant row.The rotated secret is a row that names a thing inside the row above it. It is not a card and not a nested list: it is a second row in the same card, in mono, at 55%, with no actions of its own.
