Three calls I made

Worth a yes or a no before I build

Everything else above is the system applied literally. These three are judgement, and easy to reverse now.

MCP servers has no card when nothing is found Shipped

Today it draws a card reading "none found". Windows calls an empty card furniture, so the fact moves into the footer: "…and every MCP config · no MCP config holds a key". You still learn that jit looked. The card comes back the moment there is a finding, as in frame 3.

The alternative: keep an always-present MCP card. Say the word and I will.

Card order changes by one position Shipped

Today: Agents, What agents read, Cached copies, MCP. I moved Cached copies up to second, so an agent's two facts — where its key sits, what its caches hold — sit next to each other. Order stays fixed no matter the state, so the window never rearranges itself under your cursor.

"key none found" becomes a row that says nothing is wrong Shipped

Today a missing key shows as "none found" beside a blue "add a key…" link, which reads as a problem. It is not one: no key on disk is the healthy state. The row now says "No key in a file or a keychain · nothing in the open to move" under a green eyebrow, and Add Key… stays as a quiet offer for when you do have one to paste.

The footer states, it does not act Changed in build

The draft gave frame 3's footer a Fix All 5… that would have cleaned three caches, moved a key and protected two MCP keys in one press. The repo's rule is that every button is one jit command the CLI can also send, and that batch is five commands across three kinds. It is gone. Each finding's action stays on the card that found it, and the footer says what jit checked and when.

This also fixed a bug I had written in. The first build put Clean Caches… in the footer and on the card: the same button twice for the same file, which is finding 6 in the list above. One button now, on the card.

The banner offers jit's own words, not an Undo Changed in build

An Undo beside "Removed 1 cached copy" would run jit migrate undo, which reaches further than the one file the sentence names. Instead the banner carries What jit Did…, which opens exactly what the command printed. Honest, and one click away.

No search field, and the filter only when it earns its place Changed in build

A search field over at most eleven rows is furniture. It is gone. The segmented filter now appears only when there are four cards and at least one of them needs you, which is frame 3 and never frame 1.

MCP configs are protected one file at a time Changed in build

Protect All… on the MCP card was the same cross-kind batch. Each file is its own jit migrate <file> --yes behind its own dialog, so the button lives on the row.

What I would change in the repo

  • AgentsView.swift rebuilt on AppWindowKit — Win, AppCard, AppCardRows, AppRow, AppButton, WindowMark, WindowEmptyState, windowRegion(). The same kit the Scan and Doctor windows already use, so no new components.
  • AgentsFindings.swift: AgentsSection deleted. Its uppercase heading and hard-coded 8 / 12 / 2 pt values are what AppCard replaces.
  • The window becomes Design.Window.medium with minimum(for:), and its title becomes "AI Agents" — StatusItemController.swift:46.
  • Every tooltip string moves into a card note or a row fact. Nothing load-bearing stays in .help().
  • A banner region so a finished action reports in the window, per the repo's own "no terminal pane reports success" rule.
  • No engine change. Every button is the same jit command it is today: jit wrap, jit migrate, jit grant, the cache clean.

On the data in these frames. Every path, profile and key name above is invented — ~/code/notion-sync/.env, notion/API_KEY, aws-prod. Your screenshot showed a real path from a real repo, and the brand book's rule is that a published image comes from a demo vault, never a real one. If you want these frames to mirror your actual Mac for review, that is fine — just don't publish them.
