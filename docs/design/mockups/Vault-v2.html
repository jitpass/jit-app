Vault window v2, and Reviewed findings

Two of the six items from 2026-09-28 change a window, so they start here. The Vault loses its cramped button bar and its fixed-height Settings pane. Findings gets a way to say "I checked this, it's not live" so a test fixture stops coming back.

Every name, path and value below is made up. The other four items are fixes, already built and tested on branches: the Protect row leaving at once, 24-hour decoy counts, Service reading Doctor, and scan reading export KEY=value.

1 · The Vault today

What the screenshot shows, point by point.

Six buttons in one barReveal, Copy, Replace, History, Move Out and Delete share the strip under the table with the secret's name and "used by", so at 720pt they crowd and the name truncates.
Settings can't growThe Settings pane is capped at 180pt with its own scroll, under a table that fills the rest with empty striped rows. There's no divider to drag.
"dotenv" says nothingThe Class column shows where a value came from in jit's words. The reader wants to know what the value is.
Backups in the sidebar"601 migrate backups" and Maintenance… sit under the profile list and read as part of it.

2 · Vault v2

One scroll instead of two panes. The profile's secrets and settings are two cards on the same scroll, so a long settings list makes the window scroll, not a 180pt box. Each row carries its own verbs: Reveal and Copy as buttons, the rest in the row's ⋯ menu. The bar under the table is gone. Maintenance moves to the window's footer.

3 · Reveal, and the row's menu

A reveal opens under its own row, where the eye already is, with its countdown and Hide. The row's ⋯ holds everything that is not an everyday verb, with Delete last and apart.

4 · Findings: what Test fixtures is for

The tab lists real-looking keys in test files and docs. They don't count toward the score and are almost always fake, but nothing let you say so, so they came back after every scan. The new note says what the tab is for, and each row gets Mark Reviewed. A reviewed finding leaves Findings and comes back only if the value on that line changes.

5 · What the engine needs

The app is never the only way to do something, so marks are a jit command first. A mark is stored as a keyed hash of the value, never the value, so the file of marks isn't a list of secrets.

PieceWhat it does
jit scan review FILE[:LINE]…Marks the findings on those lines. Stores path, line, finding kind and an HMAC of the value under a key kept beside it, in ~/Library/Application Support/jitpass/scan-reviewed.json.
jit scan unreview FILE[:LINE]…Removes marks. jit scan review --list prints them, no values.
jit scanDrops a finding whose path and value hash match a mark, and says so: summary reviewed: N, schema 0.25.0. A mark matches by value, so an edit that moves the line keeps it. A changed value does not match.
--unfilteredShows reviewed findings again, tagged [reviewed], like every other filter it already reveals.
Not forVault copies and agent-cache copies. Those are exact copies of secrets jit already holds, so the fix is Redact or rotate, never a mark.

Decisions for you

  • 1. Row verbs: Reveal and Copy as buttons, the rest in ⋯The alternative is all verbs behind ⋯ and right-click, which gives a quieter table but hides the two verbs used every day.Recommend: Reveal + Copy visible.
  • 2. Drop the Class columnReplace "dotenv" with the scan's name for the value when there is one, in the fact line. Nothing is shown otherwise. Sorting by column goes away with the table.Recommend: drop it.
  • 3. Where "Mark Reviewed" is offeredTest fixtures and Needs you, with the stronger question on Needs you. Not on Protect, where the answer is to protect it, and not on vault or agent-cache copies.Recommend: fixtures + Needs you.
  • 4. What brings a reviewed finding backOnly a change of the value on the line. The alternative, any edit to the file, would bring test fixtures back on every commit.Recommend: value change only.
  • 5. Name: "Mark Reviewed" or "Not a Secret""Not a Secret" is a claim the user can get wrong about a real key. "Reviewed" says only what they did.Recommend: Mark Reviewed.
